# 附件管理

## 上传附件

先进入具体项目、知识产权或普通资料文件夹，再通过上传入口选择文件；普通资料文件夹可直接保存附件和下级文件夹，不需要再创建另一类“资料记录”。支持一次选择多个文件，进度包含网络传输、加密暂存、查重判断、用户确认和服务端写库等阶段。

文件传输 100% 不是最终保存成功。只有收到明确的写库成功结果，才应认为本次上传完成。较大文件操作时不要强制结束宿主进程。

## 同名与重复内容

IPSys 使用 SHA-256 判断文件内容是否相同。同名不代表内容相同，内容相同也可能使用不同的文件名。若发现相同内容，用户可按实际需求选择共享逻辑文件、复用物理内容、独立存储或取消；不要把这种情况简单理解为“同名文件不能上传”。

**共享逻辑文件**与**仅复用相同内容的数据块**含义不同，参见 [[文件共享与版本|File-Sharing-and-Versions]]。

## 文件属性

附件的名称是必填属性。说明、标签、编号和日期可以选填；说明与标签可参与搜索。多个标签可用分号分隔，后台会统一格式。

“当前目录中显示的名称”“文件全局名称”和“当前版本的原件文件名”不必完全一致。改变全局文件属性可能影响同一 FileId 在其他关联位置的展示；仅需调整当前位置别名时，应使用对应关联入口。

## 版本与预览

同一逻辑文件可以保留多个历史版本。用户可查看并在支持的入口导出指定历史版本；默认下载通常使用最新版。

PDF 在本地浏览器中支持纵向连续滚动和按需渲染；其他格式的预览依赖软件当前支持的类型与浏览器能力。IPSys 并不自动对 Word/PDF 正文做 AI 理解或 OCR。

## 下载和导出

1. 单文件可以直接下载。
2. 文件夹、多个记录或多个附件可打包为 ZIP，并保留适当目录层级与原始文件名。
3. 较大 ZIP 使用 ZIP64 格式；浏览器系统保存和第三方解包器应按文件大小适当验证。
4. 导出不代表删除、转移或清空数据库中原来的附件。

当前代码针对单个原件设有 8 GiB 容量保护；实际大文件还依赖磁盘空间、内存、加密暂存和运行环境。[[搜索与 Excel|Search-and-Excel]] · [[日常使用|Daily-Workflow]]
