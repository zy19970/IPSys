# 故障排查

请先确认当前使用的 EXE 对应哪个版本或 Git 提交，再对照出现问题的操作步骤，不要把旧测试报告直接当作当前版本缺陷。

## 无法运行 EXE

确认下载的是 Windows x64 构建，并已从 Actions ZIP 中解压。依赖运行时版需要 .NET 8 Desktop Runtime 和 ASP.NET Core Runtime；自包含版不要求另行安装这些运行时。

出现“未知发布者”属于 Windows 对可执行文件来源的信任提示，不直接证明软件出错。先核对 GitHub 下载来源与版本，不要为了消除提示禁用系统安全功能。

## 浏览器打开但看不到资料

确认 WinForms 宿主仍在运行、已选择正确 DB、密码正确并已登录。浏览器关闭或刷新不是数据库数据丢失；本机服务若已退出，应重新启动 EXE。

## 新建目录提示“资料结构约束不允许”

如果安装了刚加入七模块多级目录的新 EXE，却仍然打开改造前创建的**旧测试数据库**，可能是旧数据库的 CHECK/父级规则没有升级。保留原 DB 备份，用最新版 EXE 新建一份独立测试库重试。若新库仍失败，再提交实际错误和操作步骤排查；不要仅凭目录名称推断为重名。

## 删除目录时原件是否全部丢失

普通删除七模块目录会将整棵目录放进回收站。恢复根目录可以找回原层级。永久删除则解除删除范围中的文件关联；其他位置仍共享的原件应继续保留。

## 彻底删除进度面板不关闭

最新设计为**全部批次真正成功后约四秒自动隐藏**。如果后台任务失败、取消或无法确认结果，则保留面板，供用户检查。旧版 EXE 可能没有新行为，请核对构建时间。

## 删除后数据库体积不下降

SQLite 会优先复用释放的空闲页，文件长度不会因删除而必然缩短。备份后通过设置执行压缩数据库，等待真正完成。

## 重复文件上传不知如何选择

相同文件名、相同内容、相同逻辑 FileId 是三种不同判断。先根据“共享文件”“复用物理内容”“独立保存”的实际目的选择；不确定时建议先取消并核对已有文件属性及版本。

## MCP 连接失败或提示宿主忙

确认软件启动、资料库已解锁、MCP 已手动授权，并且 Agent 的 `--mcp` 子进程与 GUI 在同一个 Windows 登录会话。耗时文件操作期间可能暂时繁忙；执行结果不确定时先通过原 request_id 检查状态。

## 如何提交可复现问题

请提供：软件版本或构建链接、工作区与模块、操作顺序、预期与实际结果、是否使用新库、错误文本或截图。涉及资料安全时不要公开密码、密钥、真实业务原件和敏感本地路径。
