# 文件共享、查重与版本

IPSys 的文件模型区分**文件身份、附件关联、版本历史和物理内容**。这使得同一个原件能够在适用位置重复引用，而不必每次重新保存完整字节。

| 概念 | 含义 |
| --- | --- |
| FileId | 逻辑文件身份，保存统一属性和版本链 |
| LinkId | 文件与某一目录或资料记录之间的关联 |
| FileVersion | 某个 FileId 的版本及当时的原件文件名 |
| FileObject | 存放文件内容的物理对象，可按规则复用相同字节 |
| FolderId | 目录或业务资料记录的身份，不是文件版本 |

## 三种不同的操作

**共享同一个 FileId**：不同业务位置拥有不同 LinkId，但引用同一个逻辑文件。文件全局属性和版本历史随 FileId 共享。

**独立 FileId、复用 FileObject**：逻辑文件和版本关系独立，但相同物理内容在允许的作用域中复用，以减少重复占用。

**独立保存**：逻辑文件及物理保存按独立处理方式执行。

系统通过 SHA-256 检测相同内容，但最终要由用户明确决定处理方式，不应在没有确认时静默合并版本、关联或原件。

## 删除一个位置会怎样

删除某个关联并不等于删除该 FileId 的所有版本或其他位置的链接。普通删除进入回收站时，为了恢复需要继续保留必要关联。

永久删除时，只解除指定删除范围内的 LinkId；**只有不再存在任何有效或仍可恢复的关联时，才可以回收该 FileId 与版本**。如果某物理对象仍被其他独立 FileId 使用，字节内容也不能被提前清理。

## 工作区隔离

个人工作区和公司工作区虽然位于同一个加密数据库文件内，但跨工作区操作要求物理隔离，不能直接共享同一个物理 FileObject。相应复制或转移需要遵守数据隔离规则。

## 重要提醒

1. 全局文件名称和当前位置显示别名可能不同。
2. 覆盖原件通常对应追加版本或按明确规则处理，不代表目录有版本。
3. 与别人共享同一个 FileId 前，先明确是否希望不同位置共用后续版本。
4. 不应仅凭“文件名相同”断定它们是同一逻辑文件。
