# 回收站与彻底删除

IPSys 将普通删除与永久删除分开，目的是允许恢复误删资料，同时正确处理共享原件引用。

## 普通删除

在支持多级目录的模块中，删除一个目录会将**目录及其全部下级目录、资料和附件整体移入回收站**。下级结构保留，恢复该目录即可还原原来的层级与关联。

删除具体业务记录或附件时，同样应遵循其适用的回收规则。删除前注意确认当前工作区和选中范围。

## 回收站恢复

进入回收站选择对应删除记录并恢复。对于整个已删除目录，只需恢复其根目录，就能重新显示原有树状结构；不要误以为必须逐个重建下级记录。

## 永久删除

永久删除不可按普通恢复方式撤销。对于目录树，服务端递归处理全部后代和关联；如果文件还在其他位置共享，当前删除范围只解绑相应 LinkId，不影响其他仍有效的关联和文件历史。

只有所有引用均不存在时，才能回收相关文件及版本的物理内容。操作使用事务与受控任务状态，以减少中途失败产生半完成结果的风险。

## 删除进度

永久删除较多记录或大文件时可能出现独立进度面板。**只有服务端确认全部批次成功后，成功面板才在约 4 秒后自动隐藏**；仍可以手动关闭。

如果任务失败、取消或状态不确定，面板会保留，便于读取错误并核查实际结果。进度 100% 不等于提交成功。

## 数据库文件为什么没变小

永久删除释放的空间可能先成为 SQLite 内部空闲页，供今后写入复用；数据库文件本身不一定立刻缩小。需要减少外部 DB 文件体积时，在设置中使用压缩数据库功能，并等待操作真实完成。

压缩可能需要额外可用磁盘空间。建议先安全退出并备份数据库。不要通过删除 DB 文件或随意使用外部 SQLite 工具来“清理”。
