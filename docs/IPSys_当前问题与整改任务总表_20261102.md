## 一、实施目标与统一原则

本次整改不是重做 IPSys，而是收敛现有功能，解决数据可见性、Excel 导入导出、操作一致性及并发边界的问题，保持 WinForms 启动器、本机 Explorer、SQLCipher V2、MCP 与单库个人/公司工作区的既有架构。

1. **普通资料只对应一种用户可理解的文件夹**。普通文件夹名称必填，类别、年度、标签、备注选填；可直接挂附件并嵌套目录；Folder 没有版本，File 才有版本。个人/公司相关资料模块共同遵守。`archive`、`general`、`archive_folder` 等内部 `kind` 的存量实现由开发层收敛，不能要求用户重新区分“资料记录”与“纯目录”。
2. **Excel 与页面是同一份资料台账**。Excel 导入创建或更新的资料对象，必须与手工新建的普通文件夹可相互浏览、编辑、检索及导出；Excel 主要管理名称、属性和目录归属，附件二进制另走上传/ZIP。当前固定模板：项目 11 列、知识产权 19 列、资料档案 6 列、综合资料 3 列。旧 4/1/2 列格式按现有兼容约束处理。
3. **共享原件、回收站、版本与物理空间一致**。删除单条附件关联与删除整棵文件夹是不同操作。普通删除进入回收站，恢复保持父子关系；永久删除按最后引用处理物理内容，不应错误删除仍被其他位置引用的原件。
4. **七个初始业务档案目录没有特殊系统身份**。创建后可改名、移动和删除。转移接口不可依赖“其他业务资料”等显示名称。
5. **项目编号未被确定为全局唯一**。自动更新必须能唯一识别目标，否则拒绝并报告冲突，禁止 `FirstOrDefault` 静默修改第一条。Excel 空白字段不覆盖既有有效信息。
6. **SQLCipher 与大文件完整性优先**。单文件现行上限 8 GiB；不得为性能优化引入可残留的明文临时文件，不得随意破坏 FileId/LinkId/FileVersion/FileObject 关系。用户选择“任务完成后退出”应受尊重，不能在固定 30 秒后擅自中断。
7. **当前尚未正式投产，不要求旧测试库数据迁移**；但不得自动重置、覆盖或删除用户实际资料库。所有新功能与破坏性验证使用隔离的新 SQLCipher 测试库。只修有依据的问题，维持共用组件与既有 UI 规范。

## 三、第一批：资料可靠性与模型一致性

### A01｜P0-1 普通文件夹直挂附件的回收站闭环

**现状与问题**：`RecycleStore.List()` 和 `Deleted()` 的 `v2_file` 父级类型白名单漏 `archive_folder`。删除整个目录是软删 Folder 的另一条路径，不应将两者混淆。受影响的是在普通目录内**单独删除附件的关联**后，常规回收站无法看到对应 link；数据对象未据此证明被物理删除，存在通过底层关联恢复的路径。

**修改任务**：在回收站列表、已删除项校验及恢复/永久清理路径中统一支持 `archive_folder`；检查共享 FileId、最后引用释放、父目录已删除和子目录嵌套的边界；不改变文件版本语义。

**验收标准**：单文件删除→回收站可见→恢复→原目录显示；再次删除→永久删除→无引用对象回收。共享到两处的同一原件仅在最后有效引用断开后物理回收。删除整树并恢复后子目录、附件、版本保持完整。所有异常必须返回明确结果，不能误报成功。

### A02｜N-2 统一普通资料对象、首页创建与 Excel 通道

**现状与问题**：分类内“新建”使用 `archive_folder`，首页菜单仍可新建 `archive/general`；`excel.js` 将资料模块映射到 `archive/general`，`NativeArchiveGeneralExport` 只枚举这些 kind。`archive_folder` 及其属性未纳入现行 Excel 台账，导致不同入口形成的资料无法在同一套业务操作中完全互通。

**修改任务**：

1. 先梳理普通资料模块内 `archive_folder`、`archive`、`general` 的创建、列表、详情、属性更新、上传、Excel、MCP、搜索、移动、回收站、ZIP 等**实际调用矩阵**，确定统一文件夹的唯一产品契约。
2. 将首页、分类内、右键与 Agent 创建行为统一到该契约；原则上所有普通资料新建均产生用户看来同一种“文件夹”，名称必填，其余属性选填。
3. 使 Excel 导入/导出操作与手动创建的普通文件夹相同的元数据对象。保持固定模板中“所属目录”的层级语义；导出应覆盖该模块真实有效资料，并按当前筛选范围而不是前端分页上限。
4. 同步 MCP、搜索、详情、共享/版本、回收站操作；避免仅改 Excel 列表导致其它入口继续分裂。检查旧 `archive/general` 内部实现是否可复用或收敛，不因端点注释过时就直接删除现有路由。
5. 由于仍在开发阶段，可采用新测试数据库验证新的统一数据结构；涉及已存在真实库的任何清理仍需用户明确许可。

**验收标准**：分别在公司企业资质/业务档案/综合资料/党团建设和个人相关资料模块，通过顶部、首页、右键、Excel 与 MCP 创建或更新一份资料，列表、搜索、详情、导出都能看到同一份对象。文件夹可有直接附件和下级目录；属性修改不会改变附件版本或共享关系；Excel 往返不会丢失目录归属；旧兼容模板行为按正式约定覆盖。

### A03｜P1-2 项目和综合资料 Excel 歧义更新保护

**问题**：项目以编号或名称＋类型查找后 `FirstOrDefault`；综合资料以名称＋父目录匹配后也 `FirstOrDefault`。多个候选时可能错误更新第一条。

**修改任务**：仅当目标**恰好一条**且当前策略为 `update` 时自动更新。0 条及多条分别按 `create/skip/update` 既定策略处理；多匹配 `update` 必须拒绝当前行，并报告 Excel 行号、候选记录 ID/名称及原因。不要擅自为项目编号设置数据库全局唯一索引。未来若要补充匹配键，应先依据业务规则明确项目身份。

**验收标准**：编号重复、编号为空但名称＋类型重复、综合资料同父级同名等场景，绝无无提示修改第一条；继续满足 Excel 空白不覆盖已有值。

### A04｜P2-5 搜索刷新结果一致性

**问题**：`refreshCurrent()` 重置服务端搜索状态却不清输入框，页面退回局部 `localSearch`，提示也可能消失。

**修改任务**：刷新后应保持用户正在使用的搜索语义，重新请求完整服务端检索；如果服务端检索失败，则显式提示检索失败，不允许静默把局部结果当作全局结果。处理 `searchSerial`、工作区切换与过期响应竞态。

**验收标准**：跨目录命中、删除/还原后刷新、切换工作区、快速连续输入及网络失败时，结果与提示一致，不出现“实际存在但无故消失”的误导。

### A05｜N-1 Excel 端点注释修正

**问题**：`NativeArchiveGeneralExcelEndpoints.cs` 的“only for legacy smoke fixtures”与 `excel.js` 当前调用事实矛盾。

**修改任务**：在确定 A02 的统一接口契约后同步修正注释、用户手册、Excel 字典与测试文档；不能先依据这句旧注释移除实际业务使用的 API。

**验收标准**：注释说明与实际 UI、端点、测试路径一致，现有 Excel 导入/导出不因文档清理失效。

## 四、第二批：操作与接口一致性

### B01｜P1-1 Excel `create/skip/update` 的匹配策略

`archive` 分支在区分策略前检查 `matches.Length>1`，导致已存在两条同名同目录时 `create`、`skip` 也抛错；从空库连续两行同名 `create` 实际上均能创建，原报告“两行都失败”的触发条件已撤回。`general` 分支还有多匹配静默更新，纳入 A03。

整改后应明确：`create` 是新建，允许同名时不受更新歧义校验拦截；`skip` 遇已存在记录应计为跳过并显示数量；`update` 只能唯一匹配，无匹配时的处理沿用经确认的业务策略，禁止歧义更新。先完成 A02 的统一模型再实现，避免在即将被收敛的旧接口上重复开发。

### B02｜P1-3 跨工作区业务档案转移目标

不得以 `roots.First(..."其他业务资料")` 或七个初始目录的中文名称决定归宿。改为用户明确指定目标 FolderId；UI、HTTP、MCP 的 `transfer_archive` 参数和错误文案一致。目标目录不存在、已删除、跨区无权限时，应返回具体错误。跨工作区文件物理副本应保持独立，版本与附件关系保留。

### B03｜P2-4 批量删除期间的工作区一致性

批次开始时固定工作区、会话 token、所选对象 ID 清单及预期操作结果；删除执行期间限制不兼容的工作区切换或明确中止未执行部分。所有请求使用固定作用域，不在循环中重新读取可变化的 `VaultStore.ws`。验收必须验证“删除 N 项成功、M 项失败”统计真实，并保证绝不会把 A 工作区的请求提交为 B 工作区的对象操作。

### B04｜P2-3 回收站任务进度会话变更

轮询开始时固定初始 token 与 taskId；会话锁定、换库、切 token 或任务身份不匹配时结束本轮跟踪，提示用户重新进入回收站核实真实结果。保持现有异常分支 1.2 秒间隔（原报告“无 sleep”错误），不因为客户端停止轮询就宣告后台任务已成功或已撤销。

## 五、第三批：有证据后再优化性能与并发

### C01｜P1-4 上传/下载持有 `Vault.Gate`

现状为部分网络读写在全局数据库锁内，可能使需要数据库的请求延后；不代表所有纯前端点击都被阻断。先采集正常文件、2 GiB+ 文件、限速下载、慢速上传与中断时，任务耗时、Gate 持有区间、列表/搜索响应、实际界面状态。没有可信数据前不进行事务结构重写。若改用独立连接/分块事务，必须完整验证 SQLCipher 加密边界、FileObject 状态机、最终元数据提交、取消回滚、共享引用与版本；“SQLCipher 数据库页加密”不代表附件字节在写入 SQLite 前已独立加密。禁止普通明文临时副本。

### C02｜P2-1 Excel 导入逐行全表扫描

基准数据采用 100、1000、5000 行，记录读取耗时、更新/跳过耗时和全库锁持有时间。可考虑在导入开始时建立仅用于本批的候选索引，并在每次创建后同步本批索引；不得改变 `create/skip/update`、同名归属和歧义拒绝行为。原报告“指数级”说法已撤回，按近似二次增长评估。

### C03｜P2-2 “完成后退出”的无进展场景

维持用户选择“任务完成后退出”的含义。为可能失活的任务引入可观测的实际进度与告警条件，超过合理无进展时**提示用户选择继续等待或取消退出**，不能用固定总时长或无进展时长自行强制销毁任务。正常慢速大文件、网络半开连接、磁盘写入停止与用户主动取消须分别实测。

## 六、第四批：交互约定、安全最小化与维护

### D01｜P2-6 框选后 Shift 连选锚点

代码目前框选时没有同步 `anchorId`；但锚点应为框选最后一项、起点还是最近单击项尚未冻结。参照 OneDrive/Windows Explorer 进行一致性测试后统一表格、卡片及右键选择行为，再补测试。**本项不允许先按评估者个人习惯写死。**

### D02｜P2-7 `/api/status` 返回数据库路径

未解锁状态可请求到路径属于信息最小化议题。浏览器跨域简单 GET 并不意味着跨域脚本可以读取响应；本机原生进程的可访问性是独立的威胁模型。先核实登录页路径预填和新建资料库界面是否依赖完整路径，再决定仅返回目录名、需要 token 的字段或前端改造。不要在未验证依赖前直接删除字段。

### D03｜P3-1 `last_insert_rowid()` 的重复读取

若相关写入路径被本批修改，可顺带改为使用首次返回的真实 ID，配套跨区复制/版本关联测试；目前没有已证实的生产故障，不单独扩大修改范围。

### D04｜P3-2 旧 `records` 表辅助函数

确认无活跃调用及测试依赖后清理或标记遗留逻辑；不得将其误判为当前现行 Excel API 使用错误表。

### D05｜P3-3 `position` 跨父目录递增

先证明是否会影响同级自定义排序、移动目录或新建位置。若没有实际错误，可保留现状；若要调整需确保不同父目录位置互不干扰以及历史排序可复现。
