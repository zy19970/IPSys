## 单 EXE 发布（.NET 运行时由用户自行安装）

**Windows x64 发布目录只有 `IPSys.Web.exe`，不内置 .NET 运行时。** 程序使用 WinForms + ASP.NET Core，因此首次使用的每台 Windows 10/11 x64 电脑都需要事先安装以下两项 **.NET 8 x64 共享运行时**：

1. **.NET Desktop Runtime 8（Windows x64）**：供 WinForms 主窗口使用，已包含普通 .NET Runtime。
2. **ASP.NET Core Runtime 8（Windows x64）**：供 127.0.0.1 本地 Web 服务使用。

两项均从微软官方 [下载 .NET 8](https://dotnet.microsoft.com/zh-cn/download/dotnet/8.0) 页面获取，选择各自的 **Windows x64 安装程序**。仅安装普通「.NET Runtime」或仅安装其中一项不够；不需要单独安装 IIS、ASP.NET Core Hosting Bundle 或 .NET SDK。如果电脑已经安装了这两种 .NET 8 x64 运行时，无须重复安装。可用 `dotnet --list-runtimes` 检查输出含 `Microsoft.WindowsDesktop.App 8.0.x` 和 `Microsoft.AspNetCore.App 8.0.x`。

本项目 Release 发布为 **framework-dependent / SelfContained=false / PublishSingleFile=true**。EXE 继续包含业务程序集、SQLCipher 原生依赖、HTML/CSS/JavaScript 和 PDF.js；不在 EXE 旁发布 `runtimes`、`wwwroot` 或 DLL。SQLCipher 原生库首次使用时可能解包到当前用户的临时缓存，与电脑上安装的 .NET 共享运行时不是一回事。

Visual Studio 中请使用 **项目右键 → 发布（Publish）**，选择文件夹和 Release，确保发布配置为「依赖框架 / Framework-dependent」和「生成单个文件」。也可在仓库根目录执行：

```powershell
dotnet publish src/IPSys.Web/IPSys.Web.csproj -c Release -r win-x64 --self-contained false -o .\out\IPSys-SingleExe
```

发布前请选用新的空输出目录；输出应只有 `IPSys.Web.exe`。平时 Visual Studio 的 `F5` /「生成」会产生包含 DLL 和 runtimes 的调试目录，**不应直接删除那些依赖文件或用 Debug 目录作为便携发行包**。GitHub Actions 最新成功的 `IPSys-Web-win-x64` Artifact 同样只包含一个 EXE。加密资料库 `.db` 文件仍需单独存放与手工备份。

## 最快开始测试 WinForms 启动器与网页

1. 打开 [IPSys Windows 构建工作流](https://github.com/zy19970/IPSys/actions/workflows/web-windows.yml)，选择最新成功运行，在 **Artifacts** 下载 `IPSys-Web-win-x64`。
2. 解压后双击 `IPSys.Web.exe`，点击 WinForms 唯一的“打开浏览器管理界面”按钮。**新版主界面 HTML/CSS/JS 全部编译进 EXE**，不需要外置 `wwwroot` 文件。
3. 默认显示**打开已有资料库**：输入数据库路径及密码解锁；首次使用时点击登录表单下方的「＋ 新建资料库」进入创建界面，可再点击「返回打开资料库」。解锁后**先选择公司/个人工作区**；在左侧「综合资料」中新建记录、修改资料名称、上传和下载非敏感文件；其他模块仍是示例，功能会逐项接入；通过顶部入口切换工作区，完成后安全退出。
4. 请阅读 [WEB_TESTING.md](./WEB_TESTING.md) 的细节和原型限制。本次是可以操作的**最小业务网页**，不是完整 IPSys V1.0。

## 真实项目台账（业务优先阶段）

项目业务在原加密主库内增加 `business_projects` 表，保存名称、三种固定项目类型、项目编号、负责人、承担单位、开始/结束日期、状态、分类、备注和标签。知识产权业务 B02 已接入 `business_ips` 表：保存七种固定 IP 类型、类型专属状态及 M0 所列可选申请、公开、公告、登记字段，支持真实新增、编辑、软删除、工作区内复制、跨工作区复制/转移。新增、编辑、软删除、复制到当前/另一工作区、转移到另一工作区均使用服务端权限校验及 SQLCipher 持久化。公司科研项目入口同时显示「其他项目」；个人科研与合作项目显示全部类型。**B03 项目关联合同已落库**：每份合同必须归属于一个有效项目，只能从项目详情新增；公司「全部合同」仅汇总查看、筛选；修改和软删除按工作区校验。复制项目或跨工作区转移项目时，现会在同一事务中复制所属合同并关联到新项目。合同金额 CNY 按 `0.00` 显示，未填写不视为零。项目、知识产权、合同及归档资料现在支持真实业务附件。项目连同子合同、知识产权或归档资料复制/转移时，附件引用在同一加密库中安全重连到新记录；已有综合资料附件结构保持不变。

## B05 业务附件原件与版本（本轮）

新增 `business_file_objects`、`business_file_chunks`、`business_file_links` 三张 SQLCipher 加密业务附件表，不更改已有综合资料 `records/attachments/chunks`。项目、合同、知识产权、企业资质、个人证件和成果/学术资料均在**业务详情页**上传、查看、下载及移除自己的原件。只有已存在、未删除的当前工作区记录可以接受附件；知识产权材料分类只允许「申请材料、通知文件、证书文件、其他材料」，其它业务模块不需要材料类别。同一记录下同名同类别原件按 v1、v2… 历史版本保留。单文件仍限 64 MiB，上传由安全退出任务协调控制。

复制或跨工作区转移项目时，项目附件以及其有效子合同各自的附件自动跟随到新记录；知识产权、资料归档及合同同项目复制也保留原件引用。二进制仍只在**同一加密主库内**存储，多个记录可以引用同一对象，移除附件只是软删除当前关联，不清除其它记录原件。**回收站已接入，但超 2 GiB 单文件、完整附件批量导出和 SSD 中断专项尚未验收**；本阶段仍只建议用可删除测试库验证。

## B04 资质、证件和成果归档

采用独立的 `business_archives` 加密表，遵循 M0 极简字段：**名称必填**，类别、备注和标签可选。公司「企业资质」、个人「身份与资质」、个人「成果与奖励」「学术与社会活动」均为真实记录。公司「科研成果」入口位于工作台快捷模块，不改变已冻结的左侧导航。资料先按类别卡片展示，每个类别可容纳多条台账记录，点击记录再进入独立详情；支持新增、修改、软删除、同类别复制，科研成果支持在许可的分类与公司／个人工作区之间复制或转移。**公司企业资质与个人证件是不同业务模块，不允许相互转型转移**。B05 已在 B04 的真实归档资料详情中提供原件上传、下载、移除关联及同名历史版本。
