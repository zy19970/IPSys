适用日期：2026-11-05（UTC+8）。测试对象为 Windows x64 本地资料管理系统。此文件既是操作说明，也是可直接填写的测试报告。所有结果栏初始均为“未测”，不代表已经通过。

## 一、版本和验收边界

1. **使用的 EXE**：基本功能已由 [CI #543](https://github.com/zy19970/IPSys/actions/runs/41954354575) 自动验收；本次新增**多选拖拽**修改，请使用对应最新**通过的** Windows CI 的 Artifacts 中 **IPSys-Web-win-x64-self-contained**，不要用 #543 或旧 Release 判断新拖拽功能。若新 CI 尚未通过，将这些新增用例标记 BLOCKED，勿将旧 EXE 的行为当作新版本缺陷。
2. **数据库**：必须在独立目录新建一个可丢弃的 **schema 4 测试数据库**，例如 D:\IPSys-QA\IPSys-Manual-QA.db，且与已有资料库不重名。旧 schema 2/3 数据库不兼容，不应通过本次测试执行迁移或覆盖。
3. **自动化背景**：CI #541 为 completed/success；26 个成功步骤、0 失败、2 个可选 ZIP64 步骤跳过。HTTP 14 PASS / 1 个压缩进度视觉 BLOCKED；Edge 14 PASS。自动通过仅说明覆盖的程序行为，不等于以下人工用例已经通过。
4. **安全边界**：所有删除、永久删除、共享、批量操作和压缩只作用于新建测试库。不要使用唯一资料库、生产资料或重要原件。不要为测试断电、强制结束进程、拔出外接盘或故意制造磁盘空间不足；此类破坏性故障演练需要单独方案。
5. **结果状态**：PASS（符合预期）；FAIL（可复现异常）；BLOCKED（环境缺失或客观无法继续，写明原因）；未测（尚未操作）；N/A（功能在此环境确实不适用，注明原因）。不能将 BLOCKED 或 N/A 统计为 PASS。

## 二、准备可复现的测试数据

1. 在 EXE 附近或独立磁盘文件夹创建 D:\IPSys-QA\Input、D:\IPSys-QA\Export、D:\IPSys-QA\Evidence 三个测试目录（路径可以自行修改）。分别准备一个两页 PDF、一张 PNG、一个小型 XLSX、UTF-8 Markdown（含表格、勾选框、代码块和危险 HTML）、一个 TXT，以及内容不同的两个 TXT 文件：**版本一.txt** 内容“版本一测试内容 111”，**版本二.txt** 内容“版本二测试内容 222”。这些文件必须是可丢弃的测试样例。
2. 新建数据库后在**公司工作区**创建两个项目：“验收-项目甲”“验收-项目乙”。在“验收-项目甲”下建立 **D1-待移动 → D2-待回收 → D3-藏于回收目录** 的三级目录；在 D3 上传版本一.txt，并通过该文件的**新增版本**操作增加版本二.txt，确保属于同一份逻辑文件的两个历史版本。
3. 在公司“综合资料”模块创建独立的 **G1-待清理 → G2-待回收 → G3-隐藏子级** 三级目录，另建“验收-共享源”“验收-共享目标”“验收-独立副本目标”“验收-排序甲／乙／丙”等测试文件夹。测试前记下各目录名称、附件名称及两版文字内容；若界面能显示 FileId、LinkId、SHA，可同时记录。
4. 个人工作区单独创建“验收-个人文件夹”，用于验证工作区隔离。所有数据仅用于本次试验。**不要提前删除 D2、G2**；应按第三部分 R1 的顺序执行，确保能验证“已删除中层目录和被隐藏的未删除后代”。

**执行顺序**：先完成环境、目录与版本（A/B），再做 R1 核心移动和清理（C），之后执行通用交互与安全（D/E）。同一测试库中重复用例时，新建带序号的目录，避免同名冲突影响结论。

## 四、关键结果应该如何核对

### 4.1 R1 原位移动与历史版本

1. 在删除 D2 前，确认 D3 里的两个版本确实能分别下载。若测试版本一、版本二是两个不同 FileId，先纠正测试准备。
2. 删除 D2 后，不再从普通目录中看到 D2/D3；但 D1 仍正常显示。
3. 选 D1 执行移动，目标为**同一公司工作区的综合资料根目录**；这是模块间原位移动，不是“共享”、不是“独立复制”。
4. 在回收站中找到 D2，检查模块/位置。恢复 D2 后进入 D1→D2→D3，下载历史两个版本，并核对原始内容。
5. 对另建的 G1/G2/G3 重复“删除中层→移动根→删除根→永久清理根”，验证不会因为隐藏子目录归属错误导致清理失败。
6. 若有 FileId、LinkId、版本 SHA 的界面/下载证据，移动前后分别记录；如果 UI 无法查看 ID，可用文件名、历史版本字节和完整目录路径作为人工证据，但不要冒称已从数据库验证 ID 一致。

### 4.2 共享与独立复制的判断

1. **共享/关联**：同一逻辑附件出现在不同文件夹，移除其中一个位置的关联不应删除另一处仍引用的版本内容。
2. **独立复制**：源和副本应能独立新增版本、独立删除；副本的版本变化不应反写源文件。两者即使内容相同，也不能以“SHA 一样”直接认定属于同一个 FileId。
3. **移动**：来源目录消失、目标目录出现，原有目录身份与附件版本保持。选择器中项目与普通文件夹只能选择合法目标，不能挂载到自己的后代。

### 4.3 压缩数据库的判断

1. 手动压缩只作用于专用测试库；先确认该库中确有一些已**永久清理**的测试数据。
2. 观察点击前的 DB 总大小、已用/空闲估计、二次确认、任务期间的阶段提示和最终状态。
3. 压缩不承诺实时精确百分比；如果库很小或没有空闲页，DB 文件体积**不明显下降不能单凭这一点判为 FAIL**。应优先检查压缩完成、资料库可重新打开、原有记录和附件无损。若无法观察短暂进度，记录 BLOCKED 及现象，对应自动测试中 T-P1-07 的遗留视觉观察项。
4. 检查完成提示是否自动消失，任务中切换工作区/关库是否遵守安全约束。

### 4.4 用户本机界面问题取证

1. 对同一页面至少保存一张 100% 缩放截图和一张 125% 缩放截图，截图命名建议为 E01-100-项目.png、E01-125-项目.png。
2. 若表头、复选框或操作列错位，尽量同时截取**整个表头、第一行数据与浏览器缩放比例**；说明 Windows 缩放和浏览器页面缩放是两个不同设置。
3. 若出现“点击无反应”，记录操作前选择了什么、点击哪个按钮、是否出现短暂忙碌提示；不要反复快速点击导致产生多份重复记录。
