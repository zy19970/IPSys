## 一、执行目标与权限

本次目标是在功能完整性收敛后，对真实 **WinForms 宿主 + Microsoft Edge + 本地 HTTP API + SQLCipher V2** 做一次独立、端到端、可审计的系统验收。验证数据正确性、交互闭环、安全边界、异常处理、长任务及稳定性。

本地 Agent 可创建、修改、复制、移动、归档、还原和 **永久删除独立测试库** 中的测试记录及测试文件；可执行用户认可的 **一键清空回收站**。禁止访问、覆盖、压缩、删改正式库、用户原有目录、生产附件，亦不可用正式库做大文件压测。代码修改须与验收报告分离：**先测试并留下失败证据，未经确认不以修代码或削弱断言代替复现**。

准备：新建独立路径，例如 C:\IPSys-Agent-QA\RUN-<时间戳>\，子目录 vault、files、exports、evidence、logs；保存测试库路径和所有种子记录 ID。若测试操作会改变测试数据，先记录快照与文件 SHA；跨区转移、永久清理分到独立子库或在快照之后执行。

## 二、启动与证据规范

1. 核实当前 work/onedrive-file-manager HEAD，完整 Windows CI 对应 SHA 及最新运行结果；记录 .NET/VS/Edge/Windows 版本、机器 CPU/RAM/磁盘空余、分辨率和缩放比例；检查工作区无未经授权的改动。
2. VS 或仓库构建脚本编译，启动真实 WinForms 和其打开的 Edge；所有业务动作从真实 UI 完成，同时允许用本地 API、MCP、SQLCipher 只读查询及日志核对后台状态，**后台 API 成功不能替代 UI 实测**。
3. 数据种子使用固定前缀 QA-PHASE2-<RUN_ID>，在公司和个人工作区准备各类记录；附件至少准备有效两页 PDF、图片、文本、Office、两个版本不同 SHA 的文件、33 MiB 文件。需要生成 >2GiB 数据时先核实磁盘与时间，资源不足记录 BLOCKED 不造假。
4. 每条用例给出状态 **PASS / CONFIRMED_BUG / IMPLEMENTATION_GAP / BLOCKED / TEST_ERROR**，记录执行时刻、工作区、输入 ID、请求/响应关键字段、数据库变化、原件 SHA、截图或日志位置。PASS 必须来自实测；未做的项目不得填 PASS。
5. P0 是数据正确性、数据安全或高风险阻断；P1 是主要能力/稳定性；P2 为次要视觉或易用性。优先先运行 P0，再 P1，所有不可逆删除集中在快照之后，特别留意共享引用与跨区物理隔离。

## 五、缺陷独立裁决

发现异常后，Agent 应记录原始失败日志与屏幕证据，再在新的一组测试记录或测试库中执行至少一次独立复现。需要区分 UI/JS 入口错、后端事务逻辑错、数据库损坏或引用关系错、环境不足、测试脚本误判。对跨区共享、永久清理、旧原件历史不可读、事务部分提交、误删非选中行、会话绕过等数据安全问题标 P0；普通主要功能失效标 P1；UI 纯排版且功能可用通常标 P2。

不要盲目信任 Agent 自身报告。最终报告应同时附独立证据和对任何不确定性、遗漏场景、无法复现问题的解释。不可因达到某个通过率而修改阈值、降低测试标准或伪造异常处理结果。
